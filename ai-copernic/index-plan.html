Copernic Index Plan

Your clouds are already indexed, so use them. Index only your own disk, keep that index on your computer, and never put any of it on the internet.

Your answers changed the plan. Because it's for you alone, there's no need for a public server, user accounts or Elasticsearch. Google Drive and Dropbox now work on the search page. What's left is your system disk.

What changed from Rev 1

What we know for certainThe Claude desktop app can run a connector that lives on your own computer, and a page on claude.ai can call it. So the index of your disk can stay on your disk and still appear in the same search box. Nothing is exposed to the internet, so Rev 1's riskiest decision no longer applies.

The phases

Each phase ends with a test. If it fails, stop and rethink before building the next one.

  1. Idone 2026-10-02

    Search Google Drive and Dropbox from one box

    Live on the search page. Press Enter and both drives are searched at once, alongside any files you drop on the page. Ask Copernic reads matching passages from both drives before it answers.

    Pass ifyou use it on at least 5 of 7 days for the next two weeks.

  2. IIhalf a day

    Count what's actually on the disk next

    Before indexing anything, run a read-only scan that counts files and total size by type and by top-level folder. The 8 TB is probably mostly photos, video and app data; documents are usually a small slice. The scan tells us which it is, so we size the index from facts.

    • Output: a table of documents, PDFs, images, video and archives, with how much space each takes.
    • Also check: which Drive and Dropbox folders are synced to this disk, so the same files aren't indexed twice.

    Pass ifyou can name the folders worth searching, and the size of the documents in them.

  3. III1–2 weeks

    Copernic on your computer

    A small program that crawls the chosen folders, extracts text from Office files, PDFs, zips and web pages, and stores it in one SQLite file with full-text search. It re-checks for changes on a schedule. It also runs as a local connector for the Claude desktop app, so the search page's "This computer" source lights up.

    • OCR in tiers. Scanned PDFs and screenshot or scan folders get OCR from Tesseract, running on your computer. Camera photos are skipped by default; OCRing hundreds of thousands of holiday photos costs days of processing and adds little.
    • Skipped: video, audio, system and app folders, caches, and cloud folders already searched through phase I.
    • It reads your files and never changes or deletes them.

    Pass ifa file you edit can be found with its new text within 15 minutes, and a search across all three sources answers in under 2 seconds.

  4. IVonly if needed

    Search by meaning

    Add meaning-based search to the local index, so "late delivery penalties" finds a clause that says "2% credit per week". Build this only if keyword search keeps missing things you know are there.

    Pass ifit beats keyword search on 20 real questions you write down in advance.

Dropped from Rev 1

  • A rented server and Elasticsearch. Too much running cost and upkeep for one user.
  • A public Copernic connector on Vercel. It isn't needed when the connector runs on your own computer.
  • Indexing all 8 TB. We index the folders where text lives, and skip media and system files.
  • Accounts, permissions and meaning-based search up front. They don't help a personal tool on day one.

What would sink it

Starting a crawl of all 8 TB with OCR switched on and waiting weeks for it to finish. Indexing the Drive and Dropbox folders synced to your disk, which would show every result twice. A crawler that slows the computer while you work; it should run at low priority and pause on battery.
